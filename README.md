# 揭棋 · JieQi

> 用 **Phaser 4 + phaser-mvvm** 写的**揭棋**（中国象棋变种）人机对战游戏，竖屏手机画面、中国古风，
> 通过 **Cordova** 打包成签名的 Android APK。

![开局](docs/screenshot.png)

揭棋的趣味在于**你连自己的子是什么都不知道**：开局除将帅外全部背面朝上随机摆放，走到哪一步才知道
翻出来的是什么。所以这里的 AI 不是普通的象棋 AI —— 它必须在一个**信息集**上做决策。

```
pnpm install
pnpm dev            # http://127.0.0.1:5180
pnpm test           # 69 条规则、AI、吃子提示与托盘单测
./build-android-release.sh   # 产出签名 release APK
```

## 1. 规则基线（有出处，不是猜的）

揭棋的两个权威来源互相印证，规则实现严格照此：

- QQ 象棋官方《[揭棋玩法说明](https://image.qqchess.qq.com/test_160324/activity/html/jieqiguize.html)》
- 维基百科《[揭棋](https://zh.wikipedia.org/wiki/揭棋)》

| # | 规则 | 实现位置 |
| - | ---- | -------- |
| R1 | 棋盘棋子同中国象棋（9 列 × 10 行） | `src/core/types.ts` |
| R2 | 帅/将**明子**摆在九宫原点 | `Board.deal` |
| R3 | 其余各 15 枚**暗子**随机摆放 | `Board.deal` + `rng.shuffle` |
| R4 | **暗子按其所在格位走子**：在哪个棋子的初始格位上，就按该棋子的走法走子、吃子 | `movementOf()` + `generatePieceMoves()` |
| R5 | 暗子走完**必须翻开**，原有暗子走法作废 | `Board.makeMove` |
| R6 | 暗子可以吃子，也可以被吃 | `generatePieceMoves` |
| R7 | 暗子被吃后**背面朝上**拿走，**被吃方不能翻看** | `MoveEvent.captured.kind === null` |
| R8 | 明子走法同象棋，**唯一区别：相（象）与仕（士）允许过河** | `MovementMode = 'roaming'` |
| R9 | **暗子**的仕/士**不能**出九宫、相/象不能过河 | `MovementMode = 'classic'` |
| R10 | 将死、**困毙**、长打、认输判负 | `JieqiGame.computeResult` |
| R11 | **禁止全局同形**：任何一方都不得使局面回到本局已经出现过的样子 | `selectableMoves()` / `wouldRepeat()` |
| R12 | 空步判和：双方无吃子达 40 回合（80 步） | `GameOptions.idlePlies` |
| R13 | **吃子提示**（可选）：被敌方吃得到、没有己方保护、且吃下去不会让对方送将的子 | `src/core/danger.ts` |

**R4 是全部设计的支点**，它带来两个推论：

1. **合法着法与暗子身份无关** —— 暗子的走法由格位决定，而格位是公开信息。所以"能不能走"是确定的，
   运气只体现在**翻开结果**上。
2. **暗子永远不会走第二次** —— 走完就翻开了。所以每个暗子的 `homeKind` 恒等于它所在格的种类，
   这也是 Zobrist 键不需要哈希 `homeKind` 的原因（有单测钉住这条不变式）。

### R11 禁止全局同形（比"第三次出现"更狠）

旧口径是长将/长捉（第三次重复才判），现在按**禁止全局同形**：只要某个着法会让局面回到**本局已经
出现过的任何一个局面**，这个着法就是禁止着法。判据是 Zobrist 键（含走子方），所以问的是"**局面**
回来了没有"，而不是"子摆成一样了吗"。

这条规则有三层，缺一不可，因为它们回答的是三个不同的问题：

| 层 | 位置 | 行为 |
| -- | ---- | ---- |
| 玩家 | `GameScene.play()` | 该着法**仍在**被点亮的落点里（否则玩家只会看到"点了没反应"），点下去弹**「禁止全局同形」**横幅 + 状态栏说明，**不吃子、不落子** |
| AI | `chooseMove()` 的根着法 = `selectableMoves()` | 直接**不在候选里**，搜索永远看不到它 |
| 引擎 | `JieqiGame.apply()` | 抛错 —— 就算将来某个调用方忘了问，重复局面也进不了棋谱 |

选子时的状态栏会先把话说在前面：`将 · 可走 4 处，其中 1 处禁止全局同形`。
**悔棋不算着手**：它不回答这条规则，回退掉的局面也从记录里去掉，所以退回去再走一遍是允许的。

把所有合法着法都堵死时（每个着法都会重复），轮到的这方没有一步能走的允许着法，按**困毙判负**（同 R10 的困毙，
用户 2026-09-14 拍板；旧版是 `循环重复，判和`）。与"没有合法着法"的困毙同一种收场。

### R13 吃子提示：什么才算"有危险"

三个条件同时成立才算，缺一个都不是：

1. **敌方某个子真的能走到这一格** —— 用的是真实着法表，所以炮的炮架、马的蹩腿、象的塞眼都在里面；
2. **没有任何己方子保护这一格** —— 被吃之后能立刻吃回来，就不算危险；
3. **这一步吃下去对敌方是合法的** —— 吃了会让敌方自己的将暴露（**送将**）的吃法不是威胁，
   那是对方不能走的昏招。

另有两处刻意为之：**将/帅永远不上色**（被攻击的将就是**将军**，棋盘另有光晕在报，且合法局面下它
根本不会被"白吃"）；**暗子不泄露任何东西** —— 判据只用了 `movementOf()`（公开信息）与真实着法表，
所以这层提示和玩家看到的棋盘一样，看不见暗子的身份。
实现与三条条件的单测在 `src/core/danger.ts` / `test/danger.test.ts`。

### 与 Pikafish 的交叉印证

本仓库另外对照了一个**生产级引擎**的揭棋实现 —— 凤凰（Pikafish）的
[`jieqi` 分支](https://github.com/official-pikafish/Pikafish/tree/jieqi)，它正是开源揭棋客户端
[JieqiBox](https://github.com/Velithia/JieqiBox) 用的引擎。四行代码把上面这张表钉死了：

| Pikafish 代码 | 对应的规则 |
| ------------- | ---------- |
| `constexpr std::string_view DarkPieces("RNBAKABNR"…)` | **R4** —— 暗子的类型就是它**所在格位**的类型，整张表直接由象棋初始局面摆出来 |
| `if (type_of(piece_on(from)) == ADVISOR && move_dark(m) && !(Palace & to))` | **R8/R9** —— **暗**仕/士受九宫限制，明仕/士不受 |
| `st->captureDark = is_dark(to)`（之后只清 `DARK` 位，不翻面） | **R7** —— 被吃的暗子**不翻开**，身份不对任何人公开 |
| `k ^= Zobrist::psq[DARK_PIECE][from]` | 暗子按**格位**哈希，身份不进哈希 —— 与本仓库"`homeKind` 恒等于格位类型，因而不需要哈希"是同一个结论 |

另一个参考项目 [`miaosiSari/Jieqi`](https://github.com/miaosiSari/Jieqi)（基于 elephantfish 的揭棋 AI）
的评估笔记也从侧面印证了模型：它讨论"暗车该值多少"、"对方同侧暗车已出没出"、
"揭棋没有连环士/连环相"—— 这些都是"暗子按格位走、翻开才见真章"才有的问题。

### R7 到底是谁不能看

原文是「被吃子的一方不能翻看」—— 被禁止的是**被吃的一方**，不是吃子方；吃子方是把子拿在手里
翻过来的那个人。所以本作按**观察者**建模，而不是"双方都瞎"：

```
pool(观察者, 某方) = 该方 15 个身份 − 被走子翻开过的（公开） − 这个观察者靠吃暗子学到的
```

第二项只可能落在**对方**的池子上（吃不到自己的子），这正是规则描述的那种不对称。
AI 采样世界时用的是它自己那一侧的池子。

由此，界面上的被吃子托盘分三种情况：

| 棋子怎么离场 | 托盘显示 |
| ------------ | -------- |
| 明着被吃 | 实心正面 |
| 暗着被吃，**你吃的** | **半透明正面** —— 你翻看过，所以给真面目；半透明表示吃的时候它还扣着 |
| 暗着被吃，**电脑吃的** | **背面朝上** —— 你是被吃方，不许翻看，身份根本不进视图 |
| 暗着被吃，**对局已结束** | **半透明正面** —— R7 挡的是"下棋的时候偷看"，棋下完了就没什么可挡的了（`revealHidden`） |

规则本身在 `src/vm/tray.ts`（纯函数，6 条单测），场景只负责把它画出来。

## 2. AI：在信息集上搜索

### 问题

揭棋是**不完全信息**博弈。普通 minimax 要求"当前局面"是一个确定的点，而揭棋里玩家面对的是一
**堆**可能的局面。不能用。

### 方案：PIMC（完全信息蒙特卡洛）

```
chooseMove(局面) :
    对每个采样世界 w ∈ sample(信息集, N):
        score[w] = alphaBeta(w, depth)      # 世界里一切确定，普通搜索
    平均各世界 → 每个着法的期望分
    加噪声 → 取最大
```

**信息集怎么表示**（`src/core/info.ts`）：每方维护一个"尚未翻开身份池" = 该方 15 枚原始身份
− 已经翻开的身份。池里剩下的 |pool| 个身份，分配给"仍在盘上的暗子"和"已被吃的暗子（身份永久成谜）"。
不变式是 `|池| = 盘上暗子数 + 被吃的暗子数`，每一步都有单测断言。

于是 R7 直接变成了算法的一部分：**被吃的暗子不缩小池子**，它留下的那个身份永远无法定位 ——
这正是 AI 必须平均掉的不确定性。

### 三处"一丝随机性"（都很小，都可复现）

| 来源 | 默认值（普通档） |
| ---- | ---------------- |
| 世界采样本身的期望差 | 10 个世界 |
| 每个着法的平均分加均匀噪声 | ±12 厘兵 |
| 以 ε 概率在"距最优 ≤ slack"的着法里随机挑 | ε = 5%，slack = 55 厘兵 |

噪声远小于一个有意义的差距（约 100 厘兵 = 一兵），所以它会偶尔换个同样好的走法，
但不会走出昏招。三者都由 seed 驱动，`__JIEQI__.newGame(seed)` 能完整复现一局。

### 搜索本身

alpha-beta + 置换表 + MVV-LVA 排序 + 杀手/历史启发 + 静态搜索（吃子），有节点与时间双预算。
揭棋分支因子低（20–35），所以深度 3–4 在手机上可行。

## 3. 架构

```
src/
├─ core/   规则引擎 —— 零 Phaser、零 DOM，纯 Node 可测
│  types · board(Zobrist/走子撤销) · moves(走法生成/攻击检测)
│  rules(合法性/将军/胜负/禁止全局同形) · danger(吃子提示判据) · info(信息集与采样) · notation(中文记谱) · rng
│  spin(定先后的几何：转多少、哪个面朝上、谁先行)
├─ ai/     评估 · 搜索 · PIMC 驱动
├─ ui/     古风调色板与字体 · 程序化贴图 · 棋子视图 · 棋盘视图 · 抽子棋子 · 设置对话框 · 动画库
│          字体加载（WOFF2 → document.fonts）· 加载页（DOM，进度条）
├─ vm/     ViewModel（ref/computed）· 本地偏好（难度 / 吃子提示）· 被吃子托盘规则
├─ scenes/ BootScene 载入 → StartScene 开始界面 → DrawScene 定先后 → GameScene 棋盘
└─ debug/  验收后门 window.__JIEQI__
```

**分层的铁律**：`core`/`ai` 里不允许出现 `import Phaser` 或 `window`。规则能在纯 Node 下
单测，是"规则确实是对的"这件事唯一便宜的证明方式。

**棋盘的画法是原生 Phaser，HUD 用 phaser-mvvm。** 这也是框架自己的建议：90 个交叉点、逐帧补间、
命中测试与 z 序是**游戏**；面板、按钮、棋谱是 **UI**。所以：

- 棋盘 = `Graphics` + `Container` + `scene.tweens`；
- HUD = Compose DSL（`Column`/`Panel`/`Row`/`Text`/`Button`/`List`/`Scroll`/`Spacer`/`Image`），
  数据来自 `GameViewModel` 的 `ref`；
- 换肤 = 一个 `setTheme(JIEQI_THEME)`，控件与文本度量一起跟着变。

### 竖屏对齐

设计分辨率 **450 × 900**，`Scale.FIT`。棋盘不写死在某个 y 上，而是**读 HUD 中间那个
`Spacer` 的 `appliedRect`**再把自己对齐过去 —— 因为 `UIRoot` 会预留刘海安全区，
写死的坐标在有缺口的手机上会错位。

### 信息在视图层的边界

`PieceView.showHidden()` **不接受任何身份参数**；`flipTo(kind)` 是唯一把身份送进视图的入口。
把"隐藏信息"挡在类型签名外面，比事后 grep `console.log` 便宜得多。
`__JIEQI__.state().view` 同理：暗子永远是 `?`。

第二个入口只有 `revealHidden(kind)`，**对局结束时**把棋盘上剩下的暗子翻开（`BoardView.revealHidden()`）。
它能成立也只因为一件事：棋已经下完了 —— 棋盘不再是秘密，而是一份记录。翻出来的子压到
`REVEALED_ALPHA = 0.6`：一眼看得清是什么，又明显不是"明着走出来"的那种子。半透明不许省，
否则复盘时没人分得清哪些子是当初扣着打赢的。同一个道理也用在被吃子托盘上（§1 的第四行）。

## 4. 美术：全部是代码画出来的

仓库里**没有任何图片资源**。木纹、云纹棋子背面、将帅圆牌、光晕、火星、花瓣，全部是
`Graphics` 命令在启动时烘焙成贴图（`src/ui/textures.ts`）。好处是包体极小、没有素材授权问题，
而且整套画风都是可 review、可 diff 的代码。

配色只有五种：紫檀、象牙、朱砂、墨、赤金。

### 字体：唯一一个真正的资源文件

正文、棋子、楚河汉界、按钮，全部用**霞鹜文楷**（LXGW WenKai，SIL OFL 1.1，见
`public/fonts/OFL.txt`）。上游是 25 MB 的 TTF，`scripts/build-font.sh` 用 pyftsubset 转成
**7.9 MB 的 WOFF2**（`public/fonts/LXGWWenKai-Regular.woff2`，转好的文件已提交，普通 clone 不需要
原字体也不需要跑脚本）。

**不做子集化是刻意的**：只收游戏当前用到的 347 个字只要 75 KB，但那样任何新加的文案都会悄悄掉回
系统衬线体 —— 这个游戏的文案全是中文，"某个字突然换了一种字形"不是小瑕疵，是看起来像 bug。
整份字库就没有这个风险。只出一个 Regular 字重：框架主题从不请求 bold/italic，第二份 8 MB 什么也换不来。

代价是它成了**冷启动时唯一要等的东西**，所以顺序是硬的：`main.ts` 先 `await` 字体，再构造 Phaser。
棋子、棋盘文字、HUD 筹码全部是 canvas 烘焙成贴图的，字形没到位就烘成了回退字体、而且**永远不会重画**。
等待期间压在画布上的是 DOM 加载页（`index.html` + `ui/loading.ts`），`ui/font.ts` 流式下载并按**字节**
报进度，接着 BootScene 报音频队列的进度；字体到位那一刻浏览器会自己把「揭 棋」重排成霞鹜文楷 ——
玩家看到的第一屏就是用正字写的。

## 5. 加载页、开始界面与「定先后」

四个场景，按一次会话真实走过的顺序排：**载入 → 开始界面 → 定先后 → 棋盘**。只有第一个是自动启动的，
另外两个靠 `scene.start(key, data)` 显式交接 —— 这样"玩家执什么颜色"就是一个**从抽子场景传给棋盘
的参数**，而不是某个全局变量，忘了同步也编译不过。

载入那一屏不是 Phaser 场景而是 DOM（`index.html` 里的 `#boot-veil`），理由不是省事：它要报进度的两件事
（7.9 MB 的字体、3 MB 的音乐）都发生在**还没有东西可渲染**的时候，而且 Phaser 在没有字体的情况下
也画不出用该字体写的进度条。它是整个会话里唯一一个 `screen() === "boot"` 的窗口。

### 5.1 开始界面

| 入口 | 行为 |
| ---- | ---- |
| **开始游戏** | 淡出，进入定先后 |
| **难度设置** | 同一份难度对话框：简单 / 普通 / 困难，各自标出"多少个世界 · 深度"（难度差的是**代价**也是棋力，一秒多的思考时间应当在下决定前就看到）。选择写进 `localStorage`。对话框里另有**吃子提示**复选框（默认关），见下 |
| **音量设置** | 同一份混音台：音乐、音效两条滑杆 + 静音。拖的时候就能听见 |

**吃子提示**是唯一的棋盘辅助显示，所以它默认**关**：开启后我方受威胁的子泛**红光**、敌方的泛**绿光**
（`BoardView.setDangerMarks`，光晕 + 呼吸的圈，画在棋子底下）。它挂在难度对话框里而不是单开一个菜单项，
因为它和难度是同一类决定 —— 你要多少帮助。落盘用**自己的一把 key**（`jieqi.hints.v1`），
和难度那把分开：两处写入共用一坨 JSON 的话，写难度就会把复选框抹掉。

菜单上那个音量入口**只写「音量设置」**，不带任何读数。两条滑杆的百分比只在对话框里 —— 一个"你改不动的
数值"挂在一个"你能按的控件"上，而且对话框一关它就过期了。

标题上方那颗棋子是**真棋子**：同一个 `SpinningPiece`，只是换成匀速常转 —— 这个游戏唯一不属于象棋的
规则，是标题页上唯一需要一眼看懂的东西。

棋盘页的顶栏留着同样两个入口（难度、音量），点开的是**同一个对话框函数**：两份混音台是滑杆写去
两个地方的最短路径。棋盘页因此多了一个「菜单」按钮，能带着确认框回到开始界面 —— 否则这个界面进去
就再也出不来了。

**「新局」不是"重新摆子，仍执原方"，而是"重新定先后"**：它把画面交还给同一个抽子场景（和菜单的
「开始游戏」走到的是同一段动画），抽到哪面就是哪面 —— 很可能换了个颜色。执子方是这局棋里唯一不由
棋盘决定的东西，换一局就该重新决定一次。

### 5.2 定先后：一枚棋子的正反面

抽子场景正中是一枚大棋子：**正面红帅、反面黑将**，它绕着竖直轴转，最后停在哪一面，玩家就执哪一方。
**红先黑后**是铁律，所以抽到黑将就是电脑开局（`startNewGame()` 里发完牌直接让 AI 走第一手）。

几何部分在 `src/core/spin.ts`，零 Phaser、有单测：

- `faceAt(θ) = cos θ ≥ 0 ? 帅 : 将` —— "停在哪一面"是一次比较；
- `faceScale(θ) = max(0.07, |cos θ|)` —— 棋子的**横向压缩**，正面 1、侧面 0.07。3D 是靠这个假的，
  平面游戏里最古老也最便宜的一招。**`scaleX` 恒为正**，否则字形会被镜像；
- `planSpin()` 抽两个**互相独立**的随机数：第一个决定**停在哪个面**（公平 50/50），第二个决定
  **要多转几圈**（偶数整圈）。分开抽是为了让转速不泄漏结果 —— 每个圈数都能通向两个面（有测试钉住）；
- `spinPhases(n)` 把 2.4 秒切成"匀速滑行 `n−1` 个半圈"+"最后一圈减速落定"，交接处的角速度**相等**
  （`settle = 3·glide/(n−1)`，正是 `Cubic.easeOut` 的起步倍率），所以看着是**一枚棋子在减速停下**，
  而不是"转着转着突然换了个动画"。

棋子的侧面单独烘了一张紫檀"边条"贴图（`TEX.discEdge`），并且**画在正反面之后**：够宽、能在侧面看清，
又会被几乎正对镜头的面自己盖住 —— 遮挡关系免费完成了透明度混合，不会在脸上拉出一道暗条。

定完之后停 1.7 秒报出结果（`红 帅 / 你执红方 · 先行`），再淡入棋盘。

### 5.3 执黑时棋盘镜像

**自己的子永远在屏幕下方**，所以抽到黑将时棋盘是从黑方视角画的：将在下、帅在上。

实现的要点是**只翻"画在哪"，不翻"是什么"**。引擎只有一套坐标（0 号格永远是黑方底线、89 号格是
红方底线），记谱、AI、棋谱全都说这套坐标；变的只是 `BoardView` 里"这个格子画在哪"这一个映射：

```
显示位置 = squareToLocal(89 - square)      // 9×10 网格绕中心转 180°，即 (x,y) → (8-x, 9-y)
被点的格子 = 89 - localToSquare(x, y)      // 同一个函数，它自己是自己的逆
```

`BoardView` 里所有的"格子 ↔ 位置"换算都走 `local()` / `logicalSquare()` 这两个方法，所以朝向只
存在于一个地方。棋子视图本身**完全不知道棋盘翻了**：它只是被放到一个坐标上，然后把自己的字正着画
出来 —— 把整个棋盘容器转 180° 会省掉这个映射，但每个"帅"都会倒过来。

板面上唯一不满足 180° 对称的是**楚河汉界**四个字（棋盘线、九宫斜线、炮位兵位的角括号都是对称的），
所以翻过来时这两个词**左右对调**，但字仍然正着写 —— 没人想倒着读楚河。开局的落子动画也读**画出来的
位置**来判断该从哪条边飞进来，于是红方的子会自动从上方落下。

音效各挑了一段新素材（`scripts/build-audio.sh` 里有出处）：转动是一段 2.38 秒的 rattle，
正好覆盖 2.4 秒的转动；落定是一记 clunk；判定是 chime。

## 6. Android 打包

```bash
./build-android-release.sh            # 签名 release APK
./build-android-release.sh --debug    # 未签名 debug APK
./build-android-release.sh --skip-web # 复用已有 dist/
```

脚本按顺序做六件事：找 JDK（`java` 常常不在 PATH 上，所以脚本自己探测 Homebrew / Android Studio JBR）、
找 Android SDK、`vite build`、建/刷新 Cordova 工程、生成密钥库、`cordova build android --release`
签名、用 `apksigner verify` 验证，最后把 APK 拷到 `release/`。

产物：`release/jieqi-<版本>-release.apk`。

> ⚠️ **versionCode 每次都要自己往上加**（`JIEQI_VERSION_CODE=3 ./build-android-release.sh`）。
> 脚本默认 1，而 Android 拒绝安装 versionCode 比已装版本低的包（`INSTALL_FAILED_VERSION_DOWNGRADE`）——
> 这个失败看起来完全不像构建失败，是装包的时候才炸。脚本在没有显式传值时会把 versionCode 打出来提醒。

> ⚠️ **密钥库与口令是提交进仓库的**，这样新克隆的机器一条命令就能出包。
> 这对样例/演示是正确的，对真实发布是**错的** —— 拿到这个文件的人可以发布一个 Android 认作你
> 本人的更新。正式发布前请自己生成密钥库、把它移出版本控制，并用环境变量传凭据
> （`JIEQI_KEYSTORE`、`JIEQI_KEYSTORE_PASSWORD`、`JIEQI_KEY_ALIAS`、`JIEQI_KEY_PASSWORD`）。

### 后门

`window.__JIEQI__`（`src/debug/backdoor.ts`）。需求允许留后门，理由是具体的：用 UI 走完整局意味着
在一堆**连玩家都看不见价值**的棋子上点一百次。

**但诚实的路径排在最前面**：`point(square)` 与 `widgetPoint(name)` 返回**屏幕坐标**，
所以验收可以用真实的 `mouse.move/down/up` 走 Phaser 自己的输入链路（§7 那些行就是这么测的）。
其余接口（`move`/`aiPly`/`autoPlay`/`undo`/`hint`）**调用的是按钮调的同一批 `GameScene` 方法** ——
后门里没有第二份规则实现。

| 接口 | 用途 |
| ---- | ---- |
| `state()` | 一次拿全：当前屏幕、回合、颜色归属、**棋盘是否镜像**、合法着法、双方可见棋盘、神视角棋盘、棋谱、信息池大小、错误数 |
| `screen()/waitForScreen()` | 现在在哪个界面（`boot` 加载页 / `start`/`draw`/`game`），以及等它出现 |
| `startGame()/redraw()/backToMenu()` | 从开始界面按「开始游戏」一路走到棋盘（**走真实动画**）、按「新局」重新定先后、退回开始界面 |
| `draw()` | 抽子场景的实时读数：`outcome`（抽签结果）、`shownFace`（动画现在露的脸）、`radians`、`settled`、`verdict` |
| `difficulty()/setDifficulty()` | 难度（与对话框共用同一份 `localStorage`） |
| `captureHint()/setCaptureHint()` | 吃子提示的开关（与对话框的复选框同一份 `localStorage`） |
| `danger()` | 吃子提示的读数：`mine`/`theirs` 是我方/敌方"有危险"的格子（直接来自规则判据），`marks` 是棋盘**实际画出来**的圈数 |
| `repetition()` | 当前合法着法按 **禁止全局同形** 分成 `allowed` / `forbidden` 两组 |
| `point(sq)` / `widgetPoint(name)` / `widgets()` | 页坐标，喂给真实鼠标：格子中心、某个具名控件中心、当前屏幕上所有具名控件 |
| `canvasRect()` | 画布在页面里的矩形 |
| `legal()` | 当前合法着法 + 中文记谱 |
| `move/tap/undo/hint/resign/newGame` | 走子、点击、悔棋、提示、认输、重开 |
| `aiPly/autoPlay` | 让 AI 代下、自动下完整局 |
| `settle()/settled()` | 等动画静止（判据是"棋子不动了"，不是"没有 tween"—— 见验收记录 V1） |
| `errors()` | 运行期错误，**验收要求恒为空** |

## 8. 已知边界

- **禁止全局同形比 QQ 原文更严**：QQ 的写法是"同一棋子连续捉同一子超过 6 回合禁着"（长将/长捉），
  这里实现成**任何**让局面回到本局出现过的样子的着法都是禁止着法 —— 意图一致（禁止无休止循环），
  而且判据只有一个 Zobrist 键，不需要"连续捉同一子"那套计数。全都禁止时判和（见 §1 R11）。
  有的平台把被迫重复判**负**，本作取的是保守的那一侧。
- **AI 的 PIMC 有策略融合（strategy fusion）的固有近似**：它在每个采样世界里都"知道"所有暗子，
  所以会比一个真正只能靠概率下注的人类更果断。它选的着法**永远是合法的**（合法性在
  所有世界里一致），但期望估计是近似的。这是 PIMC 的标准取舍。
- **每步搜索是同步的**：困难档约 0.8–1.8 秒，期间主线程被占用；世界之间让帧让画面继续动，
  但单帧内仍可能有一次几百毫秒的卡顿。真正的解法是 Web Worker，考虑到 Cordova 下
  `file://` 加载 worker 的风险，这里没有做。
- **音频的授权**：背景音乐来自需求里指定的 URL；音效来自本机的 GameBurp 2000 Game Sound FX
  音效库。两者都**按原样转码后提交进仓库**，授权状态我没有办法在本仓库内核实 —— 若要对外发布，
  请自行确认这两处素材的使用许可。
- **字体把 APK 从 6.5 MB 拉到约 14 MB**：7.9 MB 的 WOFF2 是包里最大的东西，比其余全部加起来还大。
  这是"整份字库、不做子集"的直接代价（§4），换来的是任何中文都不会掉字形。要压回去只有一条路：
  先子集化，再给"新增文案不许出现字库外的字"补一条会失败的测试。
- **冷启动解析 CJK 大字体有成本**：WebView 要把 7.9 MB 解压回上万个字形，桌面浏览器上几乎看不见，
  **低端手机上大概是几百毫秒量级 —— 但这条没有真机读数**（见上一条：产物没在真机上装过）。
  加载页至少让这段等待是可见的，而不是一块黑屏。
- **Android 产物没有在真机/模拟器上装过**。脚本跑通并产出了 V2 签名校验通过的 APK
  （badging、包内容都核对过），但"在手机上跑起来没问题"这件事**没有证据**，只有构建期证据。
- **Cordova 打包踩过两个坑**（都已修，见验收记录 V6 / V12）：`config.xml` 的颜色必须写成 Android 的
  `#AARRGGBB`，写 Cordova 文档里的 `0xAARRGGBB` 会被原样塞进 `res/values/colors.xml`，
  然后 AAPT2 报一个指向 appcompat 的、完全误导人的错误；那个 `config.xml` 的 heredoc 是**不加引号**的
  （`$VERSION_NAME` 之类要展开），所以注释里的反引号会被 shell 当命令替换执行掉。
- **抽子动画不能快进**。菜单「开始游戏」和棋盘「新局」都会走完整的 2.4 秒转动 + 1.7 秒判定，
  没有"跳过"按钮 —— 颜色是靠一次看得见的抽签定的，能跳过就等于能反复摇到满意为止。

### 为什么 vendor phaser-mvvm

phaser-mvvm 1.0.0 **尚未发布到 npm**，而本仓库必须能独立构建（离线、CI、以及 Cordova 打包脚本里）。
